② 근사 · Kingman(VUT) + Little's Law

공장별 대기시간과 리드타임 예측

기준선계산 중

수식 보기
구하는 값
공장 k 앞 버퍼의 평균 대기 Wk, 라인 리드타임 LT, 재공 WIP
근사식
Wk ≈ ((ca,k² + ce,k²) ÷ 2) · (uk ÷ (1 − uk)) · te,k
te,k = CTk ÷ Ak, uk = ra · te,k
ce,k² = c0² + 2·Ak(1 − Ak)·MTTR ÷ CTk, c0² = 0.05
cd,k² = uk²·ce,k² + (1 − uk²)·ca,k² → ca,k+1² = cd,k²
LT = Σk (Wk + 이동k + 칸 대기k), 이동k = (라인 길이 ÷ 속도) ÷ Ak = (PLEN·CTk ÷ GAP) ÷ Ak, 칸 대기k ≈ CTk ÷ 2
WIP = TH × LT (Little's Law)
가정
계획 투입 속도 ra로 차를 넣는다(첫 공장 도착 변동 ca² = 0). 칸 대기는 컨베이어 투입 칸이 올 때까지 기다리는 시간으로, VUT 식에 없어 따로 더했습니다.
기호
u 가동률 · te 실효 처리시간 · c² 변동계수 제곱 · PLEN 라인 길이(px) · GAP 차 간격 64px

이 식은 버퍼가 무한하다고 보는 열린 대기행렬입니다. 실제 버퍼는 4칸이라, 꽉 차면 앞 공장이 막히는(blocking) 현상은 식에 들어가지 않습니다.

발견 1 · 빈 자리 당김 · 게임에 반영 완료

앞 공장이 멈춰도 완성차 생산이 거의 줄지 않는다

앞 공장이 멈춰 뒤 공장 입구가 비면, 게임은 다음 차를 빈 자리만큼 앞으로 옮겨 넣습니다. 그래서 빈 자리가 라인 끝까지 흘러가지 않고, 버퍼 크기를 바꿔도 생산량이 변하지 않습니다. 실제 컨베이어에서는 빈 행거가 그대로 흘러가 출구에서 손실로 나타납니다.

// game.js · simLines()
- const d0 = last ? Math.max(0, last.d - GAP) : 0;
+ const d0 = (i === 0 && last) ? Math.max(0, last.d - GAP) : 0;

수정 전후 차이는 실험 1·2에 나와 있습니다.

발견 2 · 시간 간격 의존성 · 게임에 반영 완료

배속을 올리면 하루 생산량이 줄어든다

수정 전 게임은 한 걸음에 최대 2분씩 시간을 넘겼습니다. 차 간격 64px을 10px/분으로 움직이면 이론 간격은 6.4분인데, 한 걸음이 1분이면 7걸음(7분)이 걸립니다. 배속이 높을수록 한 걸음이 커져 택트가 늘어나고, 대시보드의 성능 P가 떨어졌습니다. 지금 게임은 0.2분씩 끊고, 투입 칸의 남은 거리를 다음 칸으로 넘겨 소수점 손실도 없앴습니다.

// game.js · advance()
- const s = Math.min(dt, 2);
+ const s = Math.min(dt, 0.2);   // 64px ÷ (10px/분 × 0.2분) = 정확히 32걸음

처음 만든 웹앱은 이력을 시트에 쌓는 데까지는 됐지만, 대시보드 숫자 일부가 코드에 고정돼 있었습니다. 게임과 같은 OEE 계산을 쓰도록 고치고, 게임 기록도 받을 수 있게 했습니다.

바꾼 것

  • 가동률고정값 92.5% 대신, 계획 가동시간에서 비가동 시간을 빼서 계산합니다.
  • OEE가용률 × 성능 × 품질로 나눠 보여 줘서 어느 쪽 손실인지 바로 보입니다.
  • 설비 목록고정 배열 대신 시트에 들어온 설비 번호로 만듭니다. 새 설비가 바로 보입니다.
  • 공장 도면미해결 이력이 있는 라인은 도면에서도 정지로 바뀝니다.
  • API?api=dashboard로 JSON을 주고, doPost로 게임 기록을 받습니다.

써 보기

웹앱은 원래 구글 Apps Script에서 돌아갑니다. 여기서는 예시 데이터로 도는 데모를 열 수 있고, 이 사이트의 게임에서 쌓인 비가동 이력도 함께 불러옵니다.

Roadmap

계획 · 근사 · 검증, 지금 어디쯤인지

데이터가 한쪽으로만 흐르면 디지털 섀도우, 분석 결과가 다시 공장을 바꾸면 디지털 트윈입니다. 계획 · 근사 · 검증 세 층을 쌓았고, 검증한 개선안을 게임 공장에 되돌려 적용하는 단계에 와 있습니다.

① 계획 완료

얼마나 고칠까

목표 대수와 예산으로 공장별 개선 단위를 고르는 정수 선형계획.

  • 공장별 사이클타임으로 실제 병목 만들기
  • 0-1 펼침으로 비선형 능력식 선형화
  • 다음: 교대·잔업을 결정변수로 추가

② 근사 완료

얼마나 기다릴까

Kingman 근사식과 Little's Law로 대기·리드타임·재공을 계산하고, 대시보드에서 실시간으로 확인.

  • 공장 사이 변동 전파(cd² → ca²)
  • 실시간 WIP = TH × LT 카드
  • 다음: 유한 버퍼 막힘을 넣은 근사

③ 검증 지금

정말 그런가

같은 규칙의 시뮬레이션으로 수백 일을 돌려 비교하고, 개선안을 주소 하나로 게임 공장에 적용합니다.

  • 평균 ± 표준편차로 계획·근사와 비교
  • 차이의 원인을 자동 해설
  • 다음: 게임 결과를 다시 받아 계획을 고치는 양방향 트윈
